# 文档协作 · DocFlow

让接手者理解功能、找到源码和必要历史，减少重复实现说明。规则唯一来源为 [RULES.md](RULES.md)；已在当前上下文加载相同规则时无需重读。

## 处理任务

1. 明确本次功能或差异范围，检查已有文档、项目导航和适用规则。新建需用户同意；已获准的创建、指定文档整理和已有文档随实现同步直接推进。
2. 查相关入口及关键依赖、配置和契约；只有设计原因或故障经验缺失时再定向查 Git/历史。当前实现、产品约定、历史结论和运行验收分别判断。不能把任何一方机械地当作另一方的替代。
3. 选一个权威落点。已有文档可承接就补充或精简；确需新建时参考 [功能说明模板](assets/功能说明模板.md)，删去不适用项，控制为约一页。中文标题；路径旁写清用途，优先链接到文件和符号名而非易漂移行号。
4. 只保留简要流程、重要边界/取舍和难以从源码恢复的经验。参数、数量、实时版本和配置指向其事实源；成果附证据，局部核对注明范围。遇到冲突先查明，不为消除差异而擅改业务约定。
5. 核对本次变化是否影响文档的流程、输入输出、入口、权限、兼容条件或验证方法。读必要调用方，不只凭“入口文件没改”认定文档有效。路径检查不能代替语义检查。
6. 按需运行 `python3 <本技能目录>/scripts/check_docs.py <明确的文档路径...>`，处理本次新增问题；工具检查中文一级标题及标准 Markdown 本地链接，不读取链接目标正文，不联网，不自动写文档。未检查的语法/锚点会标明，不能将结果称为全文已核验。
7. 新建文档接入现有项目导航，已有入口变化同步修正。报告有价值的更新、依据和未核对范围；不自动建索引、复制全局规则、提交/推送或扫描其他项目。

## 安装与统一维护

所有维护都在本目录源码中完成，勿手工编辑全局配置中的受管理区块。`RULES.md` 保存行为约定，本文保存操作方法，模板保存输出结构，三者不重复维护正文。

- 安装/更新：`python3 scripts/install.py install --clients both`。
- 只读检查：`python3 scripts/install.py check --clients both`；预览差异：将 `check` 换成 `diff`。
- 解除接入：`python3 scripts/install.py uninstall --clients both`，保留源码和项目文档。
- `--clients claude` 或 `codex` 可单独安装；`--home` 用于隔离验证，`--codex-home` 覆盖 Codex 配置目录。生产运行省略 `--home`；默认尊重已设置的 `CODEX_HOME`。
- 双客户端模式将规则正文安装到全局 `CLAUDE.md`，在全局 `AGENTS.md` 安装明确读取该规则的入口；Codex 单独模式直接安装规则正文。Skill 以符号链接安装，不覆盖已有异源目录/链接；Windows 若未允许创建符号链接会报错并回退，本机验证不能代替 Windows 验收。
- 规则区块记录内容校验值，手动修改、标记损坏或异源链接会拒绝覆盖。先检查差异并处理冲突，不能绕过检查盲目覆盖。切换客户端组合时先查看旧安装状态；移除共享规则前必须处理依赖它的 Codex 入口。
- 修改源码后更新安装并运行检查。Git 拉取不等于已安装生效；新会话加载另行验证。没有启动 hook、全库扫描或同步基线。
