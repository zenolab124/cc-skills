# 每日工作总结

精读当天所有 Claude Code 会话，生成一份结构化日报。

## 目标日期

$ARGUMENTS

如果用户没给日期参数，默认今天（北京时间）：`TZ='Asia/Shanghai' date +%Y-%m-%d`

---

## 执行流程

### 第零步：补全前一天的日报

每次运行时，先检查**前一天**的日报是否需要补全：

1. 读取 `~/daily-log/<前一天日期>.md`
2. 如果文件存在，检查末尾的元数据注释 `<!-- generated: YYYY-MM-DDTHH:MM+08:00 -->`
3. 如果生成时间 **早于** 该天时间窗口的结束时间（即前一天日期 + 1 天的 05:00），说明凌晨部分没覆盖到 → **重新生成该天日报**（走完整的第一步~第六步流程，覆盖写入）
4. 如果文件不存在或已经是完整的（生成时间 >= 窗口结束时间），跳过

这保证了不管用户什么时候跑，前一天的日报最终都是完整的。

### 第一步：发现当日活跃会话

```bash
python3 ~/.claude/skills/daily-summary/discover_sessions.py <YYYY-MM-DD>
```

输出 JSON，按项目分组，每个项目包含会话列表（已过滤 msg_count < 2 的空会话）。

如果结果为空，告诉用户"这天没有会话记录"，结束。

### 第二步：读取昨日日报

检查 `~/daily-log/<昨天日期>.md` 是否存在（如果第零步刚生成了，读取它）。后续总结时作为上下文：
- 昨天进行中的工作 → 今天是否延续
- 昨天的待办 → 今天是否跟进

### 第三步：提取会话内容

对每个需要精读的会话运行：

```bash
python3 ~/.claude/skills/daily-summary/extract_session.py <session_file> <YYYY-MM-DD>
```

脚本去掉 tool_result（占原文件 30-60%）和 thinking 块，保留用户输入、Claude 回复文本和工具调用名称。用 `>>>` 标记目标日期的消息，`---` 标注日期分界线。

**所有会话都要精读，不做裁剪或省略。** 每个会话一个 subagent，完整提取、完整阅读。

### 第四步：并行精读总结

**每个会话启动一个 subagent**（使用 Agent 工具，`model: "opus"`），传入该会话的完整提取内容。

所有 subagent 在同一条消息中并行发出。

**subagent prompt 要素**：

```
你是一个工作日志总结助手。下面是项目「{project_name}」的一段 Claude Code 会话记录。
会话可能跨天——理解完整上下文，但只总结目标日期 {target_date} 的工作。

{如果有昨日日报中该项目的段落，附上：}
昨日上下文：
{relevant_section}

输出要求：
- 中文
- 每个独立工作项用 markdown 列表格式：
  - **{简短标题}**（HH:MM - HH:MM）
    1-3 句话说清：做了什么、为什么、结果如何
- 延续昨天的工作标注"（延续）"
- 未完成的标注"（进行中）"
- 发现值得记住的决策或教训，单独列为"备注：..."
- 不要加项目标题，直接输出列表项

会话内容：
{extracted_content}
```

### 第五步：汇编日报

将所有 subagent 返回结果汇编为最终日报。

**日报模板**：

```markdown
# {YYYY-MM-DD} 星期X

{一句话概括，点出当天主线，不超过 20 字。不要逗号罗列多件事。}

## 时间线

| 时段 | CC Space | cc | cc-skills |
|------|----------|-----|-----------|
| 11:00 | 重打包、标签颜色优化 | chatgpt2api 排查 | |
| 12:00 | 暗色主题迭代、局域网排查 | | |
| ... | ... | ... | ... |

## {项目名}

### {主要工作项}（HH:MM - HH:MM）

{2-5 句话描述：做了什么、为什么、关键决策、结果}

### {次要工作项}（HH:MM - HH:MM）

{1-3 句话}

**进行中**：{该项目内未完成的事项}

#### 其他

- **{小修复/小调整}**（HH:MM - HH:MM）— 一句话描述

## {项目名2}

...

## 杂项

- **{不归属于特定项目的零散事项}** — 一句话描述

---

### 今日收获

- {非显而易见的决策、发现或教训}
```

**格式规则**：

时间线表格：
- 每行一个小时，每列一个项目（列头 = 项目名）
- 同一小时同一项目有多件事用顿号或 `→` 连接
- 跨多个小时的工作，第二小时起标注"（续）"
- 只列有活动的小时，空单元格留空
- 凌晨 00:00-04:59 的行标加 `+1` 前缀

`+1` 前缀规则：
- `+1` 只出现在**开始时间**上，表示该时刻在次日凌晨
- 跨午夜的工作项：直接写 `20:00 - 02:00`（结束时间不加 `+1`）
- 纯凌晨的工作项：写 `+1 02:00 - 04:00`（开始时间加 `+1`）
- 时间线表格中，凌晨的行标统一加 `+1`：`+1 00:00`、`+1 01:00`

工作项排版：
- 每个项目内按时间顺序排列
- **主要工作**（耗时 > 1 小时或影响面大）用 `###` 标题 + 多句描述
- **小修复/调整**（耗时 < 30 分钟的小事）收到 `#### 其他` 下，一条一句话
- **进行中**事项放在所属项目内（用加粗行标注），不单独列为全局章节

概括句：
- 不超过 20 字，点出主线方向而非列举
- 好："CC Space 暗色主题攻坚日"
- 差："解决局域网问题、新增诊断按钮、重做暗色主题、构建调度系统"

项目组织：
- 项目名用简短易读名称（`CC Space` 而非路径编码）
- `cc-space-agent` 的会话是 CC Space 桌面应用的子 agent 任务，归入「CC Space」项目名下
- 不归属于特定项目的零散工作（临时项目、一次性操作等）收到「杂项」章节
- 「今日收获」只列非显而易见的决策/教训，没有就不写
- 延续昨天的工作在描述中自然提及

### 第六步：写入文件

```bash
mkdir -p ~/daily-log
```

写入 `~/daily-log/{YYYY-MM-DD}.md`。

**在文件末尾追加生成时间戳**（用于第零步的补全判断）：

```markdown
<!-- generated: 2026-06-22T23:55+08:00 -->
```

时间戳用 `TZ='Asia/Shanghai' date +%Y-%m-%dT%H:%M+08:00` 获取。

告知用户文件路径。

## 注意事项

- **隐私**：日报存本地，但避免暴露 API key、密码等敏感信息
- **跨天会话**：提取脚本保留完整上下文并标注日期边界，subagent 理解全貌后聚焦目标日期
- **cc-space-agent**：这些是 CC Space 桌面应用的后台 agent 会话，数量多但每个都要精读
- **时区**：所有时间为北京时间（UTC+8）。一天的窗口是 07:00 ~ 次日 07:00，凌晨工作不会被拆到两天
- **当前会话**：正在进行的会话（即本次 /daily 调用本身）从日报中排除——它还没结束，不该总结
