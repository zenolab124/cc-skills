# 条目模板

六类条目的结构模板。每个条目都必须能独立被读懂，并通过“关联条目”与其他条目互链。


## domains/（功能域）

```markdown
# [功能名称]

[一句话描述这个功能域做什么]

## 架构

[文本/ASCII 架构图，展示核心组件和数据流]

## 关键文件

| 文件 | 职责 |
|------|------|
| `路径/文件名` | 一句话 |

## 核心流程

[描述主要的数据流或执行流程]

## 关联条目

- [条目名](../分类/文件名.md) — 关联原因
```

## shared/（公共模块）

```markdown
# [模块名称]

[一句话描述]

## 核心类型/接口

[列出关键的类型定义、函数签名、使用方式]

## 使用方

[谁在用这个模块，怎么用]

## 关联条目

- [条目名](../分类/文件名.md) — 关联原因
```

## decisions/（设计决策）

```markdown
---
confidence: confirmed | medium
evidence: session | code-only | both
status: current | superseded | rejected
---

# [决策标题]

[一句话描述这个决策]

## 背景

[什么问题触发了这个决策？]

## 方案对比

| | 方案 A | 方案 B |
|---|---|---|
| 优势 | ... | ... |
| 劣势 | ... | ... |

## 最终选择

[选了什么，为什么]

## 关联条目

- [条目名](../分类/文件名.md) — 关联原因
```

## integrations/（外部集成）

```markdown
# [依赖/服务名称]

[一句话描述为什么用它]

## 选型原因

[为什么选这个而不是替代品]

## 使用方式

[怎么集成的，关键配置]

## 限制与注意

[已知限制、版本要求、许可证等]

## 关联条目

- [条目名](../分类/文件名.md) — 关联原因
```

## workflows/（工作流）

```markdown
# [流程名称]

[一句话描述这个流程的目的]

## 步骤

1. [步骤描述]（涉及文件：`路径`）
2. ...

## 注意事项

[容易遗漏的点]

## 关联条目

- [条目名](../分类/文件名.md) — 关联原因
```

## pitfalls/（踩坑记录）

```markdown
---
confidence: confirmed | medium
evidence: session | code-only | both
---

# [陷阱主题]

## [具体陷阱名称]

**What**: [发生了什么]
**Why**: [为什么会这样]
**Action**: [怎么避免/解决]

[按主题分组，每个陷阱用三段式]

## 关联条目

- [条目名](../分类/文件名.md) — 关联原因
```

## 因果类条目的溯源字段

`decisions/` 与 `pitfalls/` 承载的是**代码里验证不了**的因果断言，所以必须标明这条结论有多硬、从哪来。

**confidence**

| 值 | 含义 |
|---|---|
| `confirmed` | 合并状态判定为 `merged-confirmed`（分支可达、merge commit 指名，或会话记录的 commit 在 `baseline..HEAD` 历史中） |
| `medium` | 只走到文件级命中并通过内容二次验证，或只有单一会话孤证。**必须在更新报告里单列供用户确认** |

**evidence**

| 值 | 含义 |
|---|---|
| `session` | 根因来自会话记录（最有价值的情形——`git diff` 拿不到这些） |
| `code-only` | diff 覆盖但会话零覆盖：改动来自其他人或其他机器，只能从完整 commit body、PR 引用、CHANGELOG 推断。**根因很可能缺失**，更新报告要把这类模块单列出来，提示去问对应作者 |
| `both` | 代码与会话互相印证，置信度最高 |

**status**（仅 `decisions/`）

| 值 | 含义 |
|---|---|
| `current` | 当前有效的决策 |
| `superseded` | 已被后续决策取代，保留作演变记录 |
| `rejected` | 被否决的方案。**分支已删除且未合并的实验，其因果结论归到这里**——"试过 X，因为 Y 失败了"是真知识，不该因为代码没留下就丢掉 |

多个独立会话印证同一根因 → 可升到 `confirmed`；只在一处出现的孤证下调为 `medium`，不要直接丢弃。
